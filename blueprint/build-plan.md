## Shipped (pre-Blueprint)

These landed before the Blueprint was adopted, so they have no individual spec.
Their record is `blueprint/history/features/00-pre-blueprint-log.md`.

- [x] 1. **Core member directory** - shortcode embed, login-gated REST endpoint,
  CiviCRM APIv4 query, client-side search/filter/sort, member cards, 5 minute
  transient cache
- [x] 2. **Membership wired end-to-end** - card redesign around photo, name,
  membership, and clickable contact lines; `Membership::get` query returning
  membership type; search, filter, and sort switched from chapter and job title
  to membership type
- [x] 3. **Full member details modal** - `react-modal` popup with mailing
  address, member-since date, and directional relationships; REST controller
  extended with an Address join and batched Relationship and Contact lookups
- [x] 4. **Print member directory** - print button calling `window.print()`, plus
  a `@media print` stylesheet that hides interactive chrome, reflows to two
  columns, and prevents cards from splitting across a page break

## Planned

- [ ] 5. **Card visual refresh** - restyle `MemberCard` without changing what it
  shows: add icons beside membership, email, and phone, and replace the solid
  indigo pill background on `.yamd-membership` with a treatment that does not use
  a filled background
- [ ] 6. **TypeScript migration** - convert `src/*.js` to `.ts`/`.tsx`, add a
  strict `tsconfig.json`, define `Member`, `Address`, and `Relationship` types
  for the REST payload, and add a `typecheck` command to `AGENTS.md`. PHP stays
  unchecked by decision.
- [ ] 7. **Unit tests** - add a test runner via `/tests`, cover the real logic
  (the `formatDate` timezone handling and the search, filter, and sort
  derivation), and add the `test` command to `AGENTS.md`, which turns on the
  test gate
- [ ] 8. **Chapter custom field** - map the CiviCRM chapter custom field, display
  it on `MemberCard`, and let it drive a filter dropdown. Scaffolding already
  exists as commented-out lines in the REST controller.
  **First step: find the real field name in CiviCRM > Support > API4 Explorer.**
  It will look like `GroupName.FieldName`, and nothing else in this item can start
  until it is known. Test against live data before checking this off.
- [ ] 9. **Vocation and community fields** - display vocation (married,
  consecrated, and so on), community status, and community name. Never wired.
  **First step: identify all three fields in CiviCRM > Support > API4 Explorer.**
  Same blocker as item 8, and worth doing in the same sitting.
- [ ] 10. **Member photo loading** - photos load slowly today. Show a placeholder
  until each image resolves, eagerly load only the first 9-12, and lazy-load the
  rest.
